## 2. 구현 요약

### (1) 라벨 정규화 (Standardization)

`data.json` 또는 사용자 입력 라벨의 다양성(`'+'`, `'cross'`, `'x'`, `'X'`)에 구애받지 않도록, 내부 전처리 함수 `only_normal()`을 통해 표준 라벨(`Cross`, `X`)로 일괄 변환하여 데이터 처리 및 검증의 안정성을 확보했습니다.

### (2) MAC (Multiply-Accumulate) 연산 구현

이중 `for`문 순회 방식으로 직접 구현하였습니다.


$$Score = \sum_{r=0}^{N-1} \sum_{c=0}^{N-1} (Pattern[r][c] \times Filter[r][c])$$


측정 정확도를 높이기 위해 $I/O$ 구간을 제외하고 순수 MAC 연산 구간만을 10회 반복 측정하여 평균 시간(ms)을 산출합니다.

### (3) 부동소수점 비교 및 동점 처리 정책 (Epsilon Policy)

부동소수점 연산 오차로 인한 오판을 방지하기 위해 허용 오차 상수 $\epsilon = 10^{-9}$ 기준을 적용했습니다.

* $\vert{}Score_{Cross} - Score_{X}\vert{} < 10^{-9}$ 인 경우: 동점으로 간주하여 **`UNDECIDED`** 처리
* $Score_{Cross} > Score_{X}$ 인 경우: **`Cross`** 판정
* $Score_{Cross} < Score_{X}$ 인 경우: **`X`** 판정

## 4. 트러블슈팅 (Troubleshooting)

### 이슈 1. `self.mode1_run()` 호출 시 `TypeError` 발생

* **원인:** `Mode_1` 클래스 인스턴스 뒤에 소괄호 `()`를 붙여 함수처럼 호출하려고 했으나, 클래스 내부에 `__call__` 메서드가 정의되어 있지 않아 발생함.
* **해결 방법:**
* **방법 A:** `Mode_1` 클래스의 메인 실행 함수명을 `__call__(self)`로 변경하여 인스턴스 직접 호출 가능하게 수정.
* **방법 B:** `self.mode1_run.mode1_flow()` 형태와 같이 명시적인 일반 메서드로 분리 호출하도록 수정.



### 이슈 2. `Matrix` 클래스 인스턴스 생성 시 `TypeError` 발생

* **원인:** 모드 1은 크기만 지정하는 방식(`Matrix(n_size)`), 모드 2는 크기와 데이터를 동시에 전달하는 방식(`Matrix(n_size, data)`)을 사용하여 매개변수 개수 불일치 발생.
* `TypeError: Matrix.__init__() takes 2 positional arguments but 3 were given`
* `TypeError: Matrix.__init__() missing 1 required positional argument: 'data'`


* **해결 방법:** `Matrix` 클래스의 `__init__` 메서드 매개변수에 기본값(`data: list = None`)을 추가하여 1개 및 2개 인자 전달을 모두 유연하게 수용할 수 있도록 개선함.
```python
class Matrix:
    def __init__(self, size: int, data: list = None):
        self.size = size
        self.data = data if data is not None else []

```

# 부동 소수점(Floating Point)의 원리와 연산 오차 분석

## 1. 부동 소수점이란?

컴퓨터에서 실수를 표현하는 방식은 크게 **고정 소수점**과 **부동 소수점**으로 나뉩니다.

* **고정 소수점 (Fixed Point):** 소수점의 위치를 고정해 두는 방식

* **예시:** `12.375` (정수 2자리, 소수 3자리로 고정)

* **단점:** 표현할 수 있는 수의 범위가 매우 좁음


* **부동 소수점 (Floating Point):** 소수점이 떠다니듯(Float) 움직인다는 의미


* **예시:** $123.45 \rightarrow 1.2345 \times 10^2$

* **장점:** 동일한 비트 크기 안에서 **아주 작거나 엄청나게 큰 수를 넓게 표현** 가능


---

## 2. 컴퓨터의 부동소수점 표현 구조 (IEEE 754)

부동 소수점이 아주 작거나 큰 수를 넓게 표현할 수 있는 이유는 **'과학적 표기법(Scientific Notation)'** 방식을 채택하여 **숫자의 크기(스케일)와 정밀도를 분리**했기 때문입니다.

## 📍 1. 부동 소수점이란?

* **단점:** 표현할 수 있는 수의 범위가 매우 좁음

* **장점:** 동일한 비트 크기 안에서 **아주 작거나 엄청나게 큰 수를 넓게 표현** 가능





---

## 2. 컴퓨터의 부동소수점 표현 구조 (IEEE 754)



부동 소수점이 아주 작거나 큰 수를 넓게 표현할 수 있는 이유: **숫자의 크기(스케일)와 정밀도를 분리**했기 때문입니다.

컴퓨터는 메모리를 **3개 영역**으로 나누어 실수를 저장합니다.


[ 부호 비트 (1 bit) ] + [ 지수부 (8 bits) ] + [ 가수부 (23 bits) ] = 총 32비트 (Float)


### 32비트 Float 기준 비트 구조

| 구분 | 비트 수 | 역할 및 기능 |
| :--- | :---: | :--- |
| **부호 비트 (Sign)** | `1 bit` | 양수(`0`)인지 음수(`1`)인지 결정 |
| **지수부 (Exponent)** | `8 bits` | 소수점을 이동시킬 위치 (**범위/크기 결정**) |
| **가수부 (Mantissa)** | `23 bits` | 실제 숫자의 유효숫자 데이터 (**정밀도 결정**) |

---

## 3. 부동소수점의 3가지 핵심 동작 원리

### (1) 정규화 (Normalization)

2진수로 변환한 실수를 정규화하면 맨 앞자리는 항상 `1.`로 시작합니다.

* **예시:** $1.100011_2 \times 2^3$
* 맨 앞이 무조건 `1`이므로, **컴퓨터는 이 `1`을 메모리에 저장하지 않고 생략**합니다.
* **이점:** 가수부 비트를 1비트 더 아껴서 **더 높은 정밀도**를 확보합니다

---

### (2) 편향된 지수 (Biased Exponent)

지수가 음수($2^{-4}$)가 될 경우, 2의 보수를 쓰지 않고 **고정된 값(Bias)을 더해서 양수**로 바꾸어 저장합니다.

* **32비트 Float 기준 Bias:** `127`
* **저장 과정:** 실제 지수가 `3`인 경우 $\rightarrow 3 + 127 = 130$ ($10000010_2$)으로 지수부에 저장
* **복원 과정:** 값을 읽을 때는 지수부 저장값에서 다시 `127`을 뺍니다.

---

### (3) 수의 범위 비교 (고정 vs 부동)

| 구분 | 32비트 정수 / 고정 소수점 | 32비트 부동소수점 (Float) |
| :--- | :--- | :--- |
| **최대 표현 범위** | 약 $-21\text{억} \sim +21\text{억}$ | 약 **$\pm 3.4 \times 10^{38}$** |
| **최소 표현 크기** | $1$ (정수 단위) | 약 **$1.18 \times 10^{-38}$** |

> ** 정밀도와의 등가교환:** 동일한 32비트 메모리 공간에서 표현 가능한 **전체 경우의 수($2^{32}$개)**는 변하지 않습니다. 따라서 **넓은 범위를 얻은 대신 '연속적인 정밀도'를 표기** 가능

---

## 4. 부동소수점의 한계: "오차"와 주의사항

부동 소수점은 범위가 넓은 대신 **정밀도(Accuracy)를 일부 희생**한 표기법.

### (1) 오차 발생 이유

1. **2진수 변환 한계:** 10진수 $0.1$은 2진수로 변환하면 $0.00011001100..._2$처럼 **무한순환소수**가 됩니다.
   * $0.1 \times 2 = \mathbf{0}.2$
   * $0.2 \times 2 = \mathbf{0}.4$
   * $0.4 \times 2 = \mathbf{0}.8$
   * $0.8 \times 2 = \mathbf{1}.6$
   * $0.6 \times 2 = \mathbf{1}.2 \;\rightarrow$ **패턴 무한 반복**
2. **비트 잘림:** **가수부(23비트)의 한계로 초과하는 비트는 반올림되어 버려집**니다.
3. **큰 정수에서의 정밀도 상실:** 수의 크기가 커져 **지수가 높아질수록 소수점 아래를 다룰 비트가 부족**해져 **정수 단위 오차**가 발생.

---

### (2) 실제 연산 예시: $0.1 + 0.2 \neq 0.3$

2진수로 변환된 무한 소수가 가수부에 잘려 들어가면서 미세한 왜곡이 발생합니다.

* **메모리에 저장된 $0.1$:** 약 $0.10000000000000000555...$
* **메모리에 저장된 $0.2$:** 약 $0.20000000000000001110...$

이 두 값을 연산하면 오차가 누적되어 다음과 같이 출력됩니다.

$$\begin{aligned} &\text{저장된 } 0.1 &\approx& \ 0.10000000000000000555\dots \\ + &\text{저장된 } 0.2 &\approx& \ 0.20000000000000001110\dots \\ \hline = &\text{연산 결과} &\approx& \ \mathbf{0.300000000000000044408920...} \end{aligned}$$
